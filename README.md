# Mars Colony

Real-Mars-terrain rover/drone/humanoid sim. First playable slice — see
`docs/game-plans/` in the main repo (and the approved plan this was scaffolded
from) for full scope.

## Status

**LIVE with real Mars terrain** at https://marsfleet.space/ (moved from
signal-playground-0uj.pages.dev to its own Cloudflare account/domain,
2026-08-04).

Both sites carry real NASA data generated by
`scripts/mars-terrain/prep_site.sh`:

- **Jezero** (6km, Mars 2020 CTX DTM + ortho, rust-tinted grayscale):
  OEB Landing spawn, delta front, Séítah, Cheyava Falls.
- **Gale** (9km, MSL 1m DEM + HiRISE color, stream-cropped from the 3.6GB
  source via /vsicurl/): Bradbury Landing spawn, Yellowknife Bay,
  Vera Rubin Ridge, Mount Sharp foothills on the horizon.

Verified: `sampleHeight()` within 0.25–0.7m of source-DEM ground truth
(`gdallocationinfo`), rover drives real slopes on both sites, no JS errors
headless. Spawn points and sample markers sit at their true relative
geography (see js/sites.js derivation comments).

## Dev

```bash
python3 -m http.server 8931
# open http://localhost:8931/
```

Deploy: `./scripts/deploy.sh` — stamps `version.json` (so the in-page update
checker, js/update-check.js, can detect the new build via its changing ETag),
stages the deployable files (excludes docs/, scripts/, d1/, secrets), and
runs `wrangler pages deploy` against the `marsfleet-space` Cloudflare Pages
project. Needs `.env.marsfleet` (gitignored) with `CLOUDFLARE_API_TOKEN` and
`CLOUDFLARE_ACCOUNT_ID` for that account.

### Telemetry (D1)

`functions/api/telemetry.js` is a Pages Function that logs anonymous,
consent-gated product-analytics events (app opens, mission completions, JS
errors — no save data, no PII) to a D1 database. It's inert (204-drops
events) if the `TELEMETRY_DB` binding is missing, so the site works either
way. One-time setup on a fresh Cloudflare account:

```bash
wrangler d1 create mars-telemetry                       # prints database_id
wrangler d1 execute mars-telemetry --remote --file d1/telemetry.sql
```

then bind `TELEMETRY_DB` to the Pages project (dashboard → Settings →
Functions → D1 database bindings, or the `deployment_configs` API) using
the printed `database_id`, and put the same id in `wrangler.toml` for local
`wrangler pages dev` parity. Player save/progress data is unrelated to this
— that's `js/saves.js`, entirely client-side (localStorage, optionally
synced to the player's own Google Drive via cloudsync.js).

## Controls

- **Desktop**: WASD/arrows to move, Tab to switch unit, E to collect a sample.
- **Touch**: left thumb-zone joystick to move, right thumb-zone to look
  (drone only), on-screen SWITCH UNIT / COLLECT buttons.

## Dependency versioning

Uses Three.js **latest stable** (currently 0.185.1) via CDN import map —
intentionally newer than this project's other standalone games (pinned at
0.160.1), since this game shares no vendor files with them. Re-check for a
newer stable release each work session.
